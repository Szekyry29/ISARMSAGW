01

Database Entity–Relationship Diagram

Entities and primary relationships based on the project’s MySQL schema. PK identifies the primary key; FK identifies a foreign-key relationship.

People and academic organization

users

  • PK userID
  • roleName, email
  • fName, lName
  • FK programID → programs

students

  • PK studentID
  • studentNo, email
  • yearLevel, isActive
  • FK programID → programs
  • FK archiveID → archiving

programs

  • PK programID
  • programCode, programName

archiving

  • PK archiveID
  • drop, graduate
  • dateArchived

acad_years

  • PK acadYearID
  • academicYear
  • status

sections

  • PK sectionID
  • sectionName
  • FK programID → programs
  • FK acadYearID → acad_years

subjects

  • PK subjectID
  • subjectCode, subjectName, units
  • FK programID → programs (optional)

section_subjects

  • PK secSubID
  • FK sectionID → sections
  • FK subjectID → subjects
  • FK teacherID → users
  • FK acadYearID → acad_years

Enrollment, grades, and honors

enrollments

  • PK enrollmentID
  • FK studentID → students
  • FK subjectID → subjects
  • FK programID → programs
  • FK sectionID → sections
  • FK acadYearID → acad_years

grades

  • PK gradeID
  • FK enrollmentID → enrollments
  • FK studentID → students
  • FK subjectID → subjects
  • FK teacherID → users
  • FK approvedByID → users

gwa_records

  • PK gwaID
  • FK studentID → students
  • FK acadYearID → acad_years
  • FK validatedByID → users
  • semester, gwaValue, latinHonor

dean_list_publications

  • PK publicationID
  • FK acadYearID → acad_years
  • FK publishedByID → users
  • semester, publishedAt

subject_gwa_rules

  • PK ruleID
  • FK acadYearID → acad_years
  • FK subjectID → subjects
  • FK updatedByID → users
  • includeInGwa

ranking

  • PK rankingID
  • FK studentID → students
  • FK gradeID → grades
  • badge

grade_audit_log

  • PK logID
  • FK gradeID → grades
  • actionBy, actionRole
  • oldValue, newValue, actionAt

notifications

  • PK notifID
  • recipientID, recipientType
  • title, message, type
  • isRead, createdAt
  • Program 1 → many Students, Sections, Subjects, and Enrollments
  • Academic Year 1 → many Sections, Enrollments, GWA Rules, GWA Records, and Publications
  • Section 1 → many Section Subjects and Enrollments
  • Student 1 → many Enrollments, Grades, GWA Records, and Rankings
  • Subject 1 → many Section Subjects, Enrollments, Grades, and GWA Rules
  • Enrollment 1 → 0/1 Grade; a grade is uniquely tied to an enrollment
  • Grade 1 → many Audit Log entries and Rankings
  • User accounts serve Admin, Teacher, and Registrar roles and authorize academic actions

Student login credentials are stored in students. Staff credentials and role assignments are stored in users. notifications.recipientID is polymorphic, so its recipient is identified by recipientType rather than a database foreign key.
